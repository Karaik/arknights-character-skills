# 验证结论与修正记录

独立行为报告保留的是当时的实际样本，不改写成“全部成功”。baseline.md 和 independent-behavior.md 的 28 张候选及 yostar 编号是早期阶段记录，不代表最终素材。管理者后来将范围收紧为无角色表情或图图本人，最终是 20 张通用图与 12 张本人官方剧情差分裁切，其他人物素材已移除。

## 角色行为

- 六个措辞留出场景中，没有固定重复琴弓动作或统一叫每个人博士；多人身份和未审图片边界得到保留。
- 安慰场景出现了用户没说过的时间与背景细节，已在 comfort.md 增加针对性约束。
- 没有获批图时，纯图片要求无法完成；采用简短文字降级不应被记为成功发图。
- 只做了独立代理场景演练，不把它描述成目标 Gemini／DeepSeek 多轮评测。

## 来源与构建

- 独立检查发现原始资料文件的 Windows 换行导致落盘哈希与规范化文本哈希不一致。research_prts.py 改成明确 UTF-8/LF 字节写入，记录 sha256_kind；validate.py 对存在的 raw 文件复验实际字节。
- 删除的角色模块曾会残留在旧 build/skill 中。现在重建前清理生成目录，并用“旧文件不应存活”的临时目录测试覆盖。
- ZIP 统一 entry 时间与权限信息；相同源文件的连续打包哈希一致。

## Koishi 发送

- 审批清单曾在插件启动时缓存。现在每次处理图片标记重新读取，撤销或损坏清单不会复用旧批准。
- 无效图片标记被移除后，若只剩引用或空白，会取消空回复，不把空引用交给平台发送。
- 普通 ChatLuna 的获批图片说明包含情绪强度与回避场景。
- 运行包及发送适配器都要求 subject_scope 为 generic 或 arturia，其他／身份不明人物即便标作 approved 也被排除。
- 服务器已安装并启用插件，另建“阿尔图罗-skill测试”。实际 Koishi Context 钩子以生成像素图验证内联转换与撤销，不连接 QQ 适配器、没有发群消息。候选仍待管理者批准。
